## 2. Поток данных и ответственность

```
постановщик → OperationRequest (frozen)
                 │
                 ▼
        L2 reflectAcrossLine ──► resultingState + ReflectionWitness (+ claimedResiduals)
                 │                         │
                 ▼                         ▼
              TRACE ───────────────► L7 verifyResult(claim, request, overrides?)
                                       / verifyProcess(trace, trustedRequests)
```

- **L2 — производитель.** Исполняет ровно то, что в запросе; выпускает свидетельство. Своих утверждений не проверяет.
- **L7 — получатель.** Доверяет только `OperationRequest`. `claimedResiduals` из свидетельства игнорируются, остатки пересчитываются заново [E: тесты «forged claimedResiduals» в обе стороны].
- **Тестовый оракул** (классификатор Property F) живёт только в `tests/`. Это не часть L7 и не должен ею становиться.

## 3. Что делает L7 [S, частично E]

Четыре этапа (`docs/ARCHITECTURE.md` [D], этап D прочитан в коде [S]):
A — допустимость чисел; B — привязка к запросу (`requestBound`, `witnessBound`); C — аксиомы отражения (середина и перпендикуляр); D — длины, площади, ориентация на чисто подвижных и чисто неподвижных элементах.

Семантика исходов, установленная запуском [E]:

| Ситуация | status | `orientationInverted` |
|---|---|---|
| Верное отражение, есть невырожденная подвижная грань | PASS | true |
| Все грани смешанные | PASS | **true, вакуозно** — нет статуса NOT_APPLICABLE |
| Единственная подвижная грань вырождена | UNDETERMINED | false |
| Вырожденная и невырожденная подвижные грани | PASS | true |
| Поворот 180° вместо отражения | FAIL | false |

Предикат ориентации **можно изолировать** через публичный аргумент `overrides`: при `{ epsilon: 10, areaEpsilon: 1e-7 }` остаётся единственная причина отказа — `orientationInverted = false` [E, тест NC-F1]. Раньше в этом репозитории (в том числе в моём прежнем отчёте) утверждалось обратное; это ошибка, исправлена.

## 4. Изоляция L7

`l7IndependentVerifier.ts` содержит единственный импорт — `import type` [S]. Тест `12` в `contract02.test.ts` проверяет отсутствие рантайм-импортов из L2/TRACE/`operationRequest` [E, проходит]. Это самая сильная архитектурная гарантия проекта.

## 5. Допуски

| Константа | Значение | Где работает |
|---|---|---|
| `epsilon` | 1e-7 | аксиомы, привязка свидетельства, длины |
| `areaEpsilon` | 1e-7 | сравнение площадей |
| `zeroNormalEpsilon` | 1e-12 | вырожденная нормаль прямой |
| `degenerateAreaEpsilon` | 1e-12 | вырожденная грань, оператор `<=` |

Особенность `resolveTolerances` [S]: `areaEpsilon` по умолчанию берёт **переопределённый `epsilon`**, а не собственное значение по умолчанию. Переопределив только `epsilon`, вызывающий молча ослабляет и допуск площади.

## 6. Сильные стороны

1. Разделение производитель/получатель реально выдержано в коде и проверено тестом.
2. `OperationRequest` отделён от утверждений производителя; подмена оси, разбиения и состояния отвергается [E: contract02].
3. Исходы `PASS` / `FAIL` / `UNDETERMINED` различаются; вырожденные грани не превращаются в обычный отказ.
4. Метаморфные тесты (A–F) независимы от реализации вычислителя и опираются на отдельный оракул.

## 7. Слабые стороны (подробно — в `OMR_REPOSITORY_AUDIT.md`)

1. Площадь в L7 считается по сырым координатам: при смещении ~1e8 верное отражение даёт ложный `FAIL` (D-1) [E].
2. Порог вырожденности абсолютный (D-2) [E].
3. L7 не различает «проверено» и «не применимо» для смешанных граней (вакуозная истина) [E].
4. Переопределение `epsilon` ослабляет `areaEpsilon` (D-4) [S].
5. Документация отстаёт от кода (D-6) [S].
