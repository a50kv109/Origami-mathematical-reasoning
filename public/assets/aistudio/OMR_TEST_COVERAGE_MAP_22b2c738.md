## 2. Что не покрыто тестами

1. Случайные и свойство-ориентированные входы: все фикстуры детерминированы.
2. `verifyProcess` с проверкой ориентации по цепочке шагов (мультишаг есть в contract02 №18, но без Property F).
3. Свойства A–E при больших и микро-координатах.
4. Самопересекающиеся грани, грани с отверстиями, грани из <3 вершин (площадь считается 0 → «вырождена»).
5. Веб-стенд (`src/App.tsx`, `VerificationWorkbench.tsx`): тестов нет.
6. Внешний независимый эталон (например Ori Studio): оракул независим от L7, но реализует ту же математику.

## 3. Характеризационные тесты — особый статус

`Numerical limitation D-1` закрепляет **ошибочное** поведение L7 (ложный `FAIL` при смещении 1e8). Он нужен, чтобы изменение было сознательным. При принятии патча `L7_CENTERED_AREA_PROPOSAL.patch` этот тест должен быть переписан (ожидание `PASS` при 1e8 и 1e9) — иначе он упадёт.

## 4. Проверка силы тестов Property F (мутации, вручную) [E]

17 мутаций классификатора и фикстур: границы `<`/`<=`, знак, смешанные, `some` вместо `every`, класс вырожденных, подмена поворота тождеством, три варианта ветки fixed, ширина допуска 1e-9 и 1e-3, оракул без устойчивости к сдвигу, удаление изоляции, чужой `stateId` у подделки, удаление override в D-2. Ловятся 16 из 17. Выжившая — «ветка fixed без проверки площади»: эквивалентная мутация (при неизменных вершинах площадь неизменна), проверка оставлена как избыточная. Мутации в ядре L2/L7 не проводились.

## 5. Замечание о названиях

В заголовках тестов есть метки `(R1)`…`(R6)`, `(audit)`: это идентификаторы из заданий этой фазы. После приёмки их стоит убрать, чтобы названия описывали поведение, а не историю.
