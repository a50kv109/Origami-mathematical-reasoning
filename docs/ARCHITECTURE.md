# Architecture Specification — Origami Mathematical Reasoning

**Статус:** Архитектурная спецификация (Stage 1)  
**Принцип:** Отделение математического ядра (Reasoning Core) от инструментов проектирования (Design Tools) и контура рассуждений агента (AI Skill).

---

## 1. Фундаментальные абстракции ядра

| Понятие | Назначение | Статус |
| :--- | :--- | :--- |
| **STATE** | Типизированный снимок объекта на этапе построения (Topology, Geometry, LayerOrder, Kinematics) | Концептуально определено; в 2D реализован прообраз в `PGS-2D` и `PCRS` |
| **TRANSFORMATION** | Детерминированный математический оператор с явными предусловиями применимости | Модель `REFLECTION` определена; каталог прочих операторов в разработке |
| **TRACE** | Воспроизводимая история операций, промежуточных состояний и их происхождения | Концептуально определено; требует единой схемы между L1, L2 и L7 |
| **RESULT VERIFICATION** | Независимая проверка конечного состояния объекта (без обязательной привязки к `TRACE`) | Архитектурно выделено |
| **PROCESS VERIFICATION** | Последовательная проверка всех переходов `Sᵢ → Sᵢ₊₁` на основе `TRACE` | Архитектурно выделено; ориентир — `SOL-Triad-Engine-v2` |

Главное архитектурное ограничение: запрещено объединять все характеристики объекта в единый монолитный кортеж `S = (G, A, X, L, K)`. Каждый слой работает со своей проекцией состояния через строгий контракт.

## 2. Семислойная архитектура (L1–L7)

| Слой | Название | Пространство | Ключевые операции | Текущий статус зрелости |
| :--- | :--- | :--- | :--- | :--- |
| **L1** | Topological Layer | Дискретные графы (`VertexID`, `EdgeID`, `FaceID`) | `FACE_SUBDIVISION`, `MATERIAL_CUT` | Проектирование (требуется финализация `L1 ↔ L2`) |
| **L2** | Geometric Layer | Евклидово пространство `ℝ²`, `ℝ³` | `BIND_GEOMETRY`, `REFLECTION`, `INTERSECT` | Проектирование (2D-модель `REFLECTION` рассчитана) |
| **L3** | Layer Order Layer | Комбинаторика перекрытий (Z-порядок) | `LAYER_ORDER_RESOLUTION` | Концепция (формальный алгоритм не завершён) |
| **L4** | Kinematic Layer | Непрерывные траектории `γ(t), t ∈ [0,1]` | `FOLD_KINEMATIC` | Концепция (проверка отсутствия столкновений открыта) |
| **L5** | Curved Folding Layer | Криволинейные складки и поверхности | `CURVED_APPROXIMATION`, `TRIANGULATE` | Исследовательская постановка |
| **L6** | Optimization Layer | Эвристический поиск и ранжирование | `SEARCH_CANDIDATES`, `RANK_SEQUENCES` | Исследовательская база (`Fe3uni` примитивы) |
| **L7** | Independent Verification Layer | Доказательное Zero-Trust пространство | `VERIFY_REFLECTION`, `VERIFY_TRACE` | Проектирование (универсальный верификатор не реализован) |

## 3. Межмодульные контракты

### Contract 01 — `L1 ↔ L2` (Topology ↔ Geometry)
- **Предмет:** связь дискретных идентификаторов графа (`VertexID`, `EdgeID`, `FaceID`) с координатами в `ℝ²`/`ℝ³`, версионирование состояний и передача геометрических предложений для `FACE_SUBDIVISION`.
- **Ключевое правило:** `L2` вычисляет геометрические точки пересечения, а `L1` проверяет топологическую допустимость и порождает новые идентификаторы, разделяя границы граней и диагонали сгибов (`portableId != localId`).
- **Статус:** концепция прошла содержательный аудит; требуется формальная схема и модульные тесты.

### Contract 02 — `L2 ↔ L7` (Geometry ↔ Independent Verification)
- **Предмет:** проверка 2D-аффинных операций (первый целевой оператор — `REFLECTION`) без использования кода генератора.
- **Передаваемый пакет:** исходные координаты, ось отражения `(point, direction)`, заявленное преобразование и итоговые координаты/инварианты.
- **Выходной вердикт L7:** `PASS` | `FAIL` | `UNDETERMINED` + явный код `CAPABILITY_GAP` при выходе за пределы поддерживаемой 2D-модели.
- **Статус:** следующий приоритет разработки (Phase 2).

### Последующие контракты (запланированы)
`L2 ↔ L3` (Geometry / Layer Order) · `L3 ↔ L4` (Layer Order / Kinematics) · `L4 ↔ L7` (Kinematic Verification) · `L5 ↔ L6` (Curved Folding / Optimization) · `L6 ↔ L7` (Candidate Evaluation / Verification).

---

## 4. Граница между Ядром, Навыком ИИ и Инструментами

1. **AI Skill** отвечает за перевод задачи с естественного языка в план операций, но **никогда** не выставляет вердикт `PASS`.
2. **Reasoning Core (`L1–L7`)** владеет каноническим состоянием (`CanonicalGeometryState`), строит `TRACE` и выносит детерминированный вердикт в `L7`.
3. **Tool Integration Layer** транслирует операции в форматы внешних программ (`.fold`, `.cp`, `.ori`) и возвращает результат обратно на проверку в `L7` по принципу Zero-Trust Import.
