# Origami Mathematical Reasoning (OMR)

**Тип системы:** исследовательско-инженерная инфраструктура математического рассуждения для AI-агентов.  
**Статус:** Stage 1 — Project Initiation & Architectural Design (прототипирование ядра `L2 ↔ L7` запланировано следующим этапом).  
**Архитектурная основа:** Research Report 01 — Revision 03, Architecture Overview V0.1.

---

## 1. Назначение проекта

**Origami Mathematical Reasoning (OMR)** — это не графический редактор и не очередной физический симулятор складывания бумаги. Это математическое ядро и специализированный reasoning skill, которые позволяют AI-агенту:

1. Интерпретировать семантическое описание геометрической конструкции.
2. Представлять объект в строго типизированной математической форме.
3. Выбирать допустимые операции с учётом предусловий и области применимости.
4. Формировать воспроизводимую последовательность преобразований (`TRACE`).
5. Взаимодействовать с внешними программами проектирования оригами через стандартизованный адаптерный слой.
6. Независимо проверять корректность как результата (`Result Verification`), так и процесса (`Process Verification`) по принципу **Zero-Trust**.

Оригами выступает первой экспериментальной средой для формализации перехода от двумерной развёртки к пространственной конфигурации. Долгосрочная цель проекта — переносимая математическая компетенция для смежных инженерных областей (листовой металл, упаковка, сборка панелей, CAD).

## 2. Три разделённых контура системы

| Контур | Назначение | Граница ответственности |
| :--- | :--- | :--- |
| **A. Origami Reasoning Core** | Математическое ядро (L1–L7, `STATE`, `TRANSFORMATION`, `TRACE`, `VERIFICATION`) | Не дублирует UI и рендер; выполняет детерминированные вычисления и доказательные проверки |
| **B. Origami Design Tools** | Внешние инструменты (`Ori Studio`, `Oriedita`, `Rabbit Ear`, `OrigamiSimulator`) | Редактирование развёрток, симуляция, визуализация; подключаются через Tool Integration Layer |
| **C. AI Agent Reasoning Skill** | Связующий контур рассуждения агента | Формирует план операций, но не имеет права самостоятельно объявлять математический результат доказанным |

Поток взаимодействия:

```text
NATURAL LANGUAGE → REASONING → MATHEMATICAL MODEL → OPERATION PLAN
  → TOOL ADAPTER → DESIGN SOFTWARE → RESULT → INDEPENDENT VERIFICATION (L7)
```

---

## 3. Главный принцип

**Goal-Oriented Mathematical Verification:** математическая строгость должна обеспечивать правильность инженерного результата. Единственность последовательности построения не является обязательным условием: допускаются разные траектории операций, если итоговый объект и каждый переход удовлетворяют заданным контрактам и инвариантам.
