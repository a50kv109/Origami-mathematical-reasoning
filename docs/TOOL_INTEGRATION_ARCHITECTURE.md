# Tool Integration Architecture — Слой интеграции с внешними инструментами

**Статус в `v0.1.0`:** **Архитектурное проектирование и первичный аудит** *(адаптеры в коде `src/` не реализованы; сторонние архивы исходников исключены из репозитория в Task A)*.  
**Принцип:** Origami Reasoning Core (`L1–L7`) не дублирует графические редакторы и GPU-симуляторы. Внешние программы подключаются через изолированный **Tool Integration Layer** с обязательной Zero-Trust проверкой возвращаемых состояний в `L7`.

---

## 1. Контур обмена данными (целевой)

```text
[AI Skill] → План операций (Canonical Operation Plan)
    ↓
[Reasoning Core (L1–L2)] → Каноническое состояние + Пакет команд
    ↓
[Tool Adapter] → Трансляция в формат инструмента (.fold / .cp / .ori / JSON)
    ↓
[External Design Tool] → Геометрический расчёт / симуляция / визуализация
    ↓
[Reverse Mapper] → Приведение ответа к GeometryState + Witness (unverified: true)
    ↓
[Independent Verification (L7)] → PASS / FAIL / UNDETERMINED (+ CAPABILITY_GAP в будущих версиях)
```

Обязательное правило: ни один результат, полученный от внешней программы или симулятора, не принимается как истина без независимой проверки аксиом и инвариантов в `L7`.

## 3. Целевой контракт адаптера (`ToolAdapter`, `Phase 8`)

Каждый адаптер в будущих фазах должен реализовывать четыре шага без доступа к внутреннему состоянию других слоёв:

1. **`checkCapabilities(op)`** — возвращает `SUPPORTED` или явный `CAPABILITY_GAP` (поддержка семантического отказа `CAPABILITY_GAP` запланирована на следующие фазы и отсутствует в `v0.1.0`).
2. **`toExternalPayload(canonicalState, operation)`** — преобразует каноническое состояние (например, в `FOLD` JSON).
3. **`execute(payload)`** — вызывает инструмент в изолированной среде с таймаутом.
4. **`fromExternalResult(rawResult)`** — отображает результат обратно в `GeometryState` и свидетельство с пометкой `unverified: true` до прохождения проверки в `L7`.
