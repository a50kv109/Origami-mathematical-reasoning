# Tool Integration Architecture — Слой интеграции с внешними инструментами

**Принцип:** Origami Reasoning Core (`L1–L7`) не дублирует графические редакторы и GPU-симуляторы. Внешние программы подключаются через изолированный **Tool Integration Layer** с обязательной Zero-Trust проверкой возвращаемых состояний.

---

## 1. Контур обмена данными

```text
[AI Skill] → План операций (Canonical Operation Plan)
    ↓
[Reasoning Core (L1–L2)] → Каноническое состояние + Пакет команд
    ↓
[Tool Adapter] → Трансляция в формат инструмента (.fold / .cp / .ori / JS API)
    ↓
[External Design Tool] → Геометрический расчёт / симуляция / визуализация
    ↓
[Reverse Mapper] → Приведение ответа к CanonicalGeometryState (PGS / OMR)
    ↓
[Independent Verification (L7)] → PASS / FAIL / UNDETERMINED / CAPABILITY_GAP
```

Обязательное правило: ни один результат, полученный от внешней программы или симулятора, не принимается как истина без повторного расчёта инвариантов в `L7`.

---

## 2. Статус интеграции потенциальных инструментов

Мы **не предполагаем наличие API** там, где оно не подтверждено фактической инспекцией кода или документации.

| Инструмент | Стек и форматы | Что подтверждено по переданным материалам | Что требует отдельной проверки перед интеграцией | Целевая роль |
| :--- | :--- | :--- | :--- | :--- |
| **Ori Studio** | Rust / WASM (`oristudio-cp`, `oristudio-fold`, `oristudio-layer-order`, `oristudio-geometry`) | Модульное разделение крейтов для развёртки, сгибов и порядка слоёв | Стабильный headless JS/WASM-контракт вызова из Node.js / браузера без UI | Референс L1–L4, расчёт сгибов и Z-порядка |
| **Oriedita** | Java (`.ori`, `.cp`, `.fold`), `FoldLineSet` | Реализация проверки локальной плоской складываемости вершин и экспорт развёрток | Наличие CLI / headless-режима для пакетного запуска без GUI | Эталонный валидатор плоских развёрток |
| **Rabbit Ear** | JS / TS, формат `FOLD`, `fold-validator` | Нативная среда JS/TS, графовая модель `FOLD` и встроенный валидатор | Согласование идентификаторов вершин/граней (`FOLD` index ↔ OMR `portableId`) | Обменный формат `FOLD`, валидация графа |
| **OrigamiSimulator** | JS / WebGL (фрагментные шейдеры) | Непрерывная 3D GPU-симуляция и расчёт внутреннего натяжения | Headless-экспорт 3D-координат после сходимости без WebGL-канваса в Node.js | Визуальная и 3D-приближённая симуляция (не доказательство!) |

## 3. Контракт адаптера (`ToolAdapter`)

Каждый адаптер реализует четыре строгих шага без доступа к внутреннему состоянию других слоёв:

1. **`checkCapabilities(op)`** — возвращает `SUPPORTED` или явный `CAPABILITY_GAP` (если инструмент не поддерживает толщину, криволинейные сгибы или размерность).
2. **`toExternalPayload(canonicalState, operation)`** — преобразует каноническое состояние (например, в `FOLD` JSON).
3. **`execute(payload)`** — вызывает инструмент (в песочнице с таймаутом).
4. **`fromExternalResult(rawResult)`** — отображает результат обратно в `CanonicalGeometryState` с пометкой `unverified: true` до прохождения проверки в `L7`.
