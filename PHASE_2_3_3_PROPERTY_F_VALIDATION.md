# Phase 2.3.3 Independent Property F Validation (`PHASE_2_3_3_PROPERTY_F_VALIDATION.md`)

**Объект проверки:** `PHASE_2_3_3_PROPERTY_F_SPECIFICATION.md` и фактическое поведение `src/core/l7IndependentVerifier.ts` (`Stage D`) + `tests/metamorphic.test.ts` (`[S][D][M]`).  
**Цель:** независимая проверка достаточности спецификации шести исходов, порядка приоритетов (недопущение скрытых пересечений исходов), граничных случаев и 10 обязательных геометрических сценариев.

## 1. Проверка взаимной исключимости и приоритеты классификации (КРИТИЧЕСКИЙ АУДИТ)

В ранних описаниях шесть исходов (`HOLDS`, `VIOLATION`, `FIXED_UNCHANGED`, `FIXED_CHANGED`, `MIXED_NOT_APPLICABLE`, `DEGENERATE_NOT_EVALUATED`) нередко формулировались как плоский список без формального дерева приоритетов `[D]`. Прямой анализ показывает **четыре критических пересечения**, при которых без строгого порядка приоритетов результат становится неоднозначным `[M]`:

1. **Пересечение 1: `MIXED` + `DEGENERATE` (смешанная грань с нулевой исходной площадью $|A_0| \le 10^{-12}$).**
   - *Конфликт:* в непринятом черновике (`Metamorphic_Tests_9c216e6d.pdf` `[EXTRACTED]`) сначала проверялось `isDegenerate` (`<= 1e-12`), а затем смешанность — то есть вырожденная смешанная грань получала `DEGENERATE_NOT_EVALUATED` вместо `MIXED_NOT_APPLICABLE`. Напротив, при строгой семантике разбиения (`L7 Stage D`, `l7IndependentVerifier.ts:854-859` `[S]`) смешанная грань отфильтровывается **до** расчёта площади (`if (!allMoving && !allFixed) continue;`), что соответствует `MIXED_NOT_APPLICABLE`.
   - *Требуемое правило:* **Разбиение (`ALL_MOVING` / `ALL_FIXED` / `MIXED`) должно проверяться ПЕРВЫМ**, чтобы `MIXED` никогда не затенялось вырожденностью и строго соответствовало логике фильтрации `L7 Stage D` `[M][P]`.

2. **Пересечение 2: `ALL_FIXED` + `DEGENERATE` (коллинеарная полностью фиксированная грань с $A_0 = 0$).**
   - *Конфликт:* в отчёте `PHASE_2_3_STEP_3_REPORT__2__8a9ce0cb.md` §5.4 отмечено, что неподвижные грани в кандидате классифицировались без проверки вырожденности (`FIXED_UNCHANGED`/`FIXED_CHANGED`) `[D]`, тогда как в упомянутом выше PDF вырожденность проверялась до `isFixed`.
   - *Требуемое правило:* для чисто фиксированных граней (`ALL_FIXED`) Property F проверяет сохранение координат вершин и площади (`FIXED_UNCHANGED` / `FIXED_CHANGED`), поэтому либо фиксированная вырожденная грань оценивается как `FIXED_UNCHANGED` (если координаты не изменились — т.к. проверка координат не требует ненулевой площади `[M]`), либо вырожденность ограничивается только `ALL_MOVING` гранями (как это фактически делает `L7 Stage D` на строке `895`: `if (allMoving) { if (|signed0| <= degEps) ... }` `[S]`). **Приоритет `ALL_FIXED` над `DEGENERATE` (или ограничение `DEGENERATE_NOT_EVALUATED` исключительно на `ALL_MOVING` грани) согласуется с `L7` (`[S][P]`).**

3. **Пересечение 3: Невырожденная `ALL_MOVING` грань схлопнулась в вырожденную после неверного преобразования ($|A_0| > 10^{-12}$, но $|A_1| \le 10^{-12}$).**
   - *Риск:* если вырожденность проверять по $A_1$ (или по $\min(|A_0|, |A_1|)$), то грубая ошибка генератора, схлопнувшая треугольник в линию, получит `DEGENERATE_NOT_EVALUATED` вместо `VIOLATION` `[M]`!
   - *Требуемое правило:* критерий `DEGENERATE_NOT_EVALUATED` должен проверяться **исключительно по исходному состоянию $S_0$** (`|A_0| <= degenerateAreaEpsilon`), как это и реализовано в `L7` (`l7IndependentVerifier.ts:896`: `Math.abs(signed0) <= tol.degenerateAreaEpsilon` `[S]`). При $|A_0| > \varepsilon_{\text{deg}}$ и $A_1 = 0$ исход обязан быть **`VIOLATION`** `[M]`.

4. **Пересечение 4: Неполный/некорректный `vertexIds` (`length < 3`, пустой массив, неизвестный `VertexId`, дублирующийся `VertexId` в `moving` и `fixed`).**
   - *Требуемое правило:* `face.vertexIds.length === 0` или отсутствие вершины в `moving ∪ fixed` (или попадание в оба множества) должны выбрасывать явную ошибку предусловия теста / `UNKNOWN_PARTITION` до возврата любого из 6 исходов; грань с $1$ или $2$ вершинами при `ALL_MOVING` имеет $A_0 = 0 \implies$ `DEGENERATE_NOT_EVALUATED` (`[S][M][P]`).

### Нормативный детерминированный порядок ветвления (полная исключимость) `[P]`
1. Проверка целостности ID: все `v ∈ face.vertexIds` присутствуют в `source`/`result` и строго в одном из `movingIds` / `fixedIds` (иначе — ошибка теста / `Contract violation`).
2. `MIXED` проверка (`hasMoving && hasFixed`) $\implies$ **`MIXED_NOT_APPLICABLE`**.
3. `ALL_FIXED` проверка (`allFixed`) $\implies$ неизменность всех вершин И площади $\implies$ **`FIXED_UNCHANGED`**, иначе **`FIXED_CHANGED`**.
4. `ALL_MOVING` проверка (`allMoving`):
   - `vertexIds.length < 3` ИЛИ `|A_0| <= degenerateAreaEpsilon` $\implies$ **`DEGENERATE_NOT_EVALUATED`**;
   - иначе (`|A_0| > degenerateAreaEpsilon`): `|A_1 + A_0| <= τ_area(A_0)` И `||A_1| - |A_0|| <= τ_area(A_0)` $\implies$ **`HOLDS`**, иначе **`VIOLATION`**.

*(С этим деревом 6 исходов строго взаимно исключают друг друга и полностью согласованы с `L7 Stage D` `[S][M]`.)*
