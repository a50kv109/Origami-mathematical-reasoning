## 2. Базовые проектные решения (`OD-01` — `OD-05`) и три пред-кодовые фиксации

### 2.1. Реестр `OD-01` — `OD-05`
- **`OD-01A`:** `MIXED + DEGENERATE` $\to$ `MIXED_NOT_APPLICABLE`.
- **`OD-01B`:** `ALL_FIXED + DEGENERATE` $\to$ `FIXED_UNCHANGED` / `FIXED_CHANGED` **строго по евклидовой норме координат** ($\max_i \|p_i^{S_1}-p_i^{S_0}\|_2 \le \tau_{\text{coord}}$), площадь не влияет на решение Level 5.
- **`OD-01C`:** Запрет внутренних повторов и замыкающего повтора `['A','B','C','A']` на **Level 0B** является **локальным предусловием `Property F v1`**; формат `Face2D` / `GeometryState` (`src/core/types.ts:29-32`) этим не ограничивается и остаётся открытым вопросом для **Contract 02 v3 / Phase 2.4**.
- **`OD-01D`:** Пустая грань (`vertexIds = []`) отклоняется на **Level 0B** (с документированием отличия от `L7:852` `continue`).
- **`OD-02`:** Две независимые политики: оракул ($\tau_{\text{coord}}=10^{-12}$, $\tau_{\text{area}}=10^{-12}\max(1,|A_0|)$, вырожденность $\le 10^{-12}$) vs `L7` (`epsilon=1e-7`, `areaEpsilon=1e-7`, `degenerateAreaEpsilon=1e-12`). Полоса $(10^{-12}, 10^{-7}]$ действует в области $|A_0| \le 10^5$.
- **`OD-03`:** Все **36** действующих тестов остаются побайтово неизменными (`tests/propertyF_v1.test.ts`).
- **`OD-04`:** Characterization Tests (`D-1`, `D-2`, `D-4`, `D-5`) включаются с конкретными `assert`-триггерами и процедурой перевода в `Regression` (`D-3`, `D-8` явно исключены из Property F).
- **`OD-05`:** Работа с `public/assets/aistudio/` запрещена внутри Phase 2.3.3 (`ROD-02`).

### 2.2. Три пред-кодовые фиксации владельца (подтверждено по коду `[S][E]`)
1. **Значение $\tau_{\text{coord}} = 10^{-12}$:**
   В тестовом слое фиксируется $\tau_{\text{coord}} = 10^{-12}$ (согласовано с существующей константой тестового оракула `METAMORPHIC_COORD_TOLERANCE = 1e-12` в `tests/metamorphic.test.ts:45` `[S]`, метрика — евклидова норма `Math.hypot(dx, dy)`, граница равенства `<=`). Это **не** линейный допуск `L7` (`epsilon = 1e-7`) и **не** порог нормали `L2` (`zeroNormalEpsilon = 1e-12`).
2. **Три раздельных диагностических кода `Level 0` при дефектах вершин:**
   Отсутствие и некорректность вершин не сводятся к единому неинформативному `FAIL`, а диагностируются раздельно на Level 0:
   - вершина отсутствовала уже в исходном состоянии `S0` $\to$ `UNKNOWN_SOURCE_VERTEX_ID`;
   - вершина присутствовала в `S0`, но отсутствует в результирующем состоянии `S1` $\to$ `MISSING_RESULT_VERTEX`;
   - вершина присутствует в `S0`/`S1`, но её координаты некорректны (`!Number.isFinite(x) || !Number.isFinite(y)` / `NaN` / `±Infinity`) $\to$ `NON_FINITE_VERTEX_COORDINATES`.
3. **Эпистемический принцип и граница `SHA-256` / `4aea9f4`:**
   - Тестовый слой не доказывает абсолютную корректность ядра, а ищет условия, при которых утверждения ядра перестают выполняться.
   - Локальные `SHA-256` доказывают побайтовую неизменность файлов внутри среды AI Studio (где `.git` отсутствует), но **сами по себе не доказывают побайтовую идентичность GitHub-коммиту `4aea9f4`** без отдельной внешней сверки с GitHub.
