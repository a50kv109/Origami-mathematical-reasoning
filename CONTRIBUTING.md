# Contributing to Origami Mathematical Reasoning (OMR)

Спасибо за интерес к развитию **Origami Mathematical Reasoning (OMR)**!  
Проект строится вокруг строгой математической изоляции и воспроизводимости. Перед внесением изменений ознакомьтесь с правилами ниже.

---

## 1. Ключевые архитектурные правила

1. **Изоляция `L7` от `L2` и `TRACE` (Zero-Trust Rule):**
   - Модуль `src/core/l7IndependentVerifier.ts` **не имеет права** импортировать функции, константы или утилиты среды выполнения из `l2GeometryEngine.ts` или `trace.ts`.
   - Разрешены только чистые импорты типов (`import type ... from './types'`).
   - Верификатор `L7` обязан игнорировать диагностические поля генератора (например, `witness.claimedResiduals`) и вычислять все невязки самостоятельно.
   - Запрещено дублировать алгоритм решателя `L2` в `L7` вместо независимой проверки аксиом и инвариантов.

2. **Точность вычислений в ядре:**
   - В математическом ядре `src/core/` запрещено округление координат (включая `.toFixed()`) при сохранении или передаче `GeometryState` и `ReflectionWitness`.
   - Численные допуски принадлежат принимающему верификатору (`L7`), а не состоянию `GeometryState`.

3. **Разделение контуров:**
   - Не смешивайте логику графического рендера (`src/components/`) с математическим ядром (`src/core/`).
   - Не добавляйте сторонний исходный код под несовместимыми лицензиями (например, GPL) в репозиторий OMR; интеграция с внешними программами должна происходить только через изолированные адаптеры с Zero-Trust проверкой в `L7`.

4. **Естественно-языковая честность (Epistemic Discipline):**
   - Не документируйте запланированные функции (L1 `FACE_SUBDIVISION`, L3–L6, `CAPABILITY_GAP`, адаптеры) как уже реализованные.

---

## 2. Требования к коду и тестам

- Все собственные файлы исходного кода и тестов в `src/` и `tests/` должны содержать заголовок:
  ```ts
  /**
   * @license
   * SPDX-License-Identifier: Apache-2.0
   */
  ```
- Любая новая математическая операция или правило верификации принимается только вместе с:
  - позитивным эталонным тестом (`PASS`);
  - **негативным контролем** (намеренное искажение выхода генератора, подмена параметров или разрыв `TRACE`), гарантирующим `FAIL`;
  - проверкой вырожденных входов (`NaN`, `Infinity`, нулевая нормаль), возвращающих `UNDETERMINED` без маскировки реальных ошибок.

---

## 3. Локальная проверка перед коммитом / PR

Установите зависимости чисто и прогоните все проверки:

```bash
npm ci
npm test
npm run lint
npm run build
```

Все три команды (`npm test`, `npm run lint`, `npm run build`) должны завершаться с кодом выхода `0`. Не добавляйте в репозиторий архивы (`*.zip`, `*.tar.gz`), локальные настройки IDE или секреты.
