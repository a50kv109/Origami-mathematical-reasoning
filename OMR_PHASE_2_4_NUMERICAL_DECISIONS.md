## 2. Матрица разделения допусков (`ND-06`)

Смешивание размерностей (длина $[L]$, площадь $[L^2]$, безразмерные отношения $[1]$, эпсилон-порог машинного представления) — источник ошибок `D-2` и `D-4`. Предлагаемое разделение:

| Класс допуска | Текущее поле в коде | Размерность | Назначение | Текущее поведение / проблема | Целевая политика (Phase 2.4+) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Линейный геометрический** | `epsilon` (`1e-7`) | $[L]$ | `r_mid`, `r_perp`, `maxFixedDisplacement`, `maxLengthError`, `targetDiff` | Корректно для средних масштабов ($\|p\| \sim 1..10^5$), но не масштабируется при $\|p\| \gg 10^9$ (`ULP(1e9) ≈ 1.2e-7`). | Сохранить абсолютный `epsilon` как базовый контракт, рассмотреть документирование/гибридную модель `eps_abs + eps_rel * L` для сверхбольших координат в `ND-06`. |
| **Площадной** | `areaEpsilon` (`1e-7`) | $[L^2]$ | `areaError = ||S'| - |S||` и проверка инверсии `|S' + S|` | **Дефект `D-4`:** при `overrides.epsilon` без `overrides.areaEpsilon` наследует `epsilon` (`[l7IndependentVerifier.ts:59]`). Также не учитывает периметр $P$. | **Шаг 1 (обязательно):** отвязать `areaEpsilon` от `epsilon` (`?? DEFAULT_VERIFIER_TOLERANCES.areaEpsilon`). **Шаг 2 (`ND-06`):** оценить допустимую погрешность площади $\max(\text{areaEpsilon}, \frac{1}{2} P \cdot \text{epsilon} + \frac{1}{2} n \cdot \text{epsilon}^2)$. |
| **Порог вырожденности грани** | `degenerateAreaEpsilon` (`1e-12`) | $[L^2]$ $\to$ **[1]** | Разделение невырожденной и вырожденной (коллинеарной) грани | **Дефект `D-2`:** абсолютный $[L^2]$ бракует микрограни и пропускает длинные иглы (`L=1e6, h=1e-10`). | Перевести в безразмерный критерий формы $\rho = 2|S|/D^2 \le \eta_{\text{deg}}$ (или сохранить legacy-параметр при `useLegacyAreaThreshold` / явном контракте `ND-04`). |
| **Порог нулевой нормали** | `zeroNormalEpsilon` (`1e-12`) | $[N]$ | Защита от вырожденной прямой $n = (0,0)$ | При конечных малых нормалях (`1e-160`) без масштабирования `normSq` теряет точность в субнормалах; при `1e160` ложно бросает `DEGENERATE_NORMAL`. | Разделить проверку: (a) геометрическое вырождение $\|n\|_2 \le \varepsilon_{\text{zero}}$, (b) безразмерное масштабирование на $2^{-k}$ перед возведением в квадрат. |
| **Оракульный допуск (тесты)** | `METAMORPHIC_COORD_TOLERANCE` (`1e-12`) | $[L]$ / $[L^2]$ | Проверка `L2` против независимого точного оракула в `tests/` | Не зависит от грубого `1e-7` в `L7` (документировано в `D-7` Phase 2.3.3). | Строго отделить от `L7` допусков; при сравнении **Уровень D vs Уровень C** оракул проверяет фактическую ошибку FP64-алгоритма (ULP / обусловленность). |

## 3. Матрица политики переполнения и андерфлоу для `L2` (`ND-05`)

| Сценарий в `L2` (`reflectAcrossLine`) | Текущее поведение (`[REPRODUCED]`) | Причина в коде | Целевая политика (требует выбора в `ND-05`) |
| :--- | :--- | :--- | :--- |
| **Нормаль велика (`n = (1e160, 1e160)`), результат конечен (`p = (1, 2)`)** | Бросает `DEGENERATE_NORMAL` с текстом `<= 1e-12` | `normSq = nx*nx + ny*ny` переполняется в `Infinity` ([l2GeometryEngine.ts:76,80](./src/core/l2GeometryEngine.ts#L76)) | **Масштабировать** $(n_x, n_y, c)$ на степень двойки $2^{-k}$ (без потери битов мантиссы) и вычислять корректное отражение `p' = (-2, -1)`. |
| **Нормаль мала (`n = (1e-160, 1e-160)`), `zeroNormalEpsilon = 0`** | Возвращает искажённое `p' = (-2.000033..., -1.000033...)` | `normSq ≈ 4e-320` уходит в субнормалы, теряя ~39 бит точности | При `norm > zeroNormalEpsilon` масштабировать $(n_x, n_y, c)$ вверх на $2^{+k}$ до нормального диапазона $[0.5, 2)$, восстанавливая полные 53 бита точности. |
| **Нормаль истинно мала (`||n|| <= zeroNormalEpsilon`) или нечисловая (`NaN`/`Infinity`)** | Бросает `DEGENERATE_NORMAL` / `INVALID_COORDINATE` | Явная проверка в `validateLineParams` | Сохранить без изменений (`DEGENERATE_NORMAL` / `INVALID_COORDINATE`). |
| **Координаты велики (`p = (1e308, 0), n = (1, 1), c = 0`), математический образ представим `(0, -1e308)`** | Тихо возвращает `p' = (-Infinity, -Infinity)` без throw | `2 * signedOffset` ([l2GeometryEngine.ts:312](./src/core/l2GeometryEngine.ts#L312)) переполняется | Выполнить проекцию с нормализованной $\hat{n}$ / без преждевременного умножения на `2`: `t = dot(n_hat, p) - c_hat`; `p' = p - 2 * t * n_hat` с предварительным `2^{-k}` масштабированием, чтобы `(1e308, 0)` корректно переходил в `(0, -1e308)`. |
| **Математический образ $p'$ объективно больше `Number.MAX_VALUE`** (напр. `p=(1e308, 1e308)` через прямую $x+y=-10^{308}$) | Возвращает `Infinity` / `-Infinity` в `resultingState`, затем `L7` выдаёт `UNDETERMINED` | Отсутствует проверка конечности `pPrime` в `L2` | **Требует решения:** бросать `L2EngineError('INVALID_COORDINATE', 'Reflected coordinate overflows IEEE-754 binary64')` (рекомендуется для соблюдения контракта конечных чисел `L2`), чтобы не записывать `Infinity` в `TRACE`. |

## 4. Граница минимального Phase 2.4 vs Phase 2.5+ (`ND-01`, `ND-08`, `ND-10`)

- **Phase 2.4 (минимальный, высокоэффективный контур `[ENGINEERING PROPOSAL]`):**
  1. Исправить сцепление допусков `D-4` (`areaEpsilon ?? DEFAULT_VERIFIER_TOLERANCES.areaEpsilon`).
  2. Сделать `L2` и `L7` устойчивыми к масштабу нормали и переполнениям промежуточных произведений (`D-3`, через `2^k` нормализацию и безопасную проекцию).
  3. Перевести `computeSignedArea` в `L7` (и классификацию знака) на центрированную + точную/компенсированную формулу для любых $n$-угольников (`D-1`).
  4. Обновить критерий вырожденности грани (`D-2`) после утверждения формулы и порога $\eta_{\text{deg}}$ (`ND-04`).
  5. Уточнить политику `D-5` с сохранением совместимости `Contract 02` (`ND-07`).
  6. Реализовать полностью изолированный оракул Уровней B и C в `tests/` по [OMR_PHASE_2_4_ORACLE_SPECIFICATION.md](./OMR_PHASE_2_4_ORACLE_SPECIFICATION.md).
- **Phase 2.5+ (архитектурное расширение, не блокирующее Phase 2.4):**
  - Введение `ExactGeometryState` на базе `ExactRational` / алгебраических чисел для многошаговых цепочек без промежуточного квантования в `binary64`.
  - Интервальная полусертификация через строгое битовое `Interval64` (`nextUp`/`nextDown`), если появятся нелинейные операции (пересечения, сгибы со сложными углами).
  - Реализация `L1`, `L3–L6`, `Contract 01`, `JCS + SHA-256`.
