# OMR Phase 2.4 — Implementation Readiness & Gate Criteria (`OMR_PHASE_2_4_IMPLEMENTATION_READINESS.md`)

**Назначение:** Чёткие критерии готовности (Gates) и жёсткие предусловия перед началом любой модификации исходного кода Phase 2.4, при строгом сохранении границы с Phase 2.3.3 (`ROD-03`).  
**Связанные документы:** [OMR_PHASE_2_4_NUMERICAL_DECISIONS.md](./OMR_PHASE_2_4_NUMERICAL_DECISIONS.md), [OMR_PHASE_2_4_ORACLE_SPECIFICATION.md](./OMR_PHASE_2_4_ORACLE_SPECIFICATION.md), [OMR_PHASE_2_4_REPOSITORY_VALIDATION.md](./OMR_PHASE_2_4_REPOSITORY_VALIDATION.md).

| Контур | Область изменений | Зависимость от ядра (`src/core/*`) | Статус авторизации |
| :--- | :--- | :--- | :--- |
| **`Phase 2.3.3` (`ROD-03`)** | Только тестовый слой `tests/propertyF_v1.test.ts` (6-уровневый классификатор `Property F`, 15 мутаций). | **Ядро строго заморожено** (`Phase 2.2` baseline). | `WAITING FOR EXPLICIT OWNER AUTHORIZATION` (`ROD-03`) |
| **`Phase 2.4` (Planning & Audit)** | Документация аудита, решений, спецификации оракула и валидации репозитория. | **Read-only**, ноль изменений в `src/**`, `tests/**`, конфигах. | Выполнено данным пакетом |

## 2. Предусловия допуска к кодированию (`Pre-Implementation Checklist`)

Ни одна строка в `src/core/*` или `tests/*` не может быть изменена до выполнения всех 6 условий:

1. **Утверждение решений владельцем (`ND-01` – `ND-11`):**
   - Подписан минимальный объём Phase 2.4 (`ND-01`: Scale-Safe FP64 + точная/центрированная площадь + оракул без обязательного `Interval64` / runtime `ExactRational`).
   - Утверждена политика общего кода `L2`/`L7` (`ND-02`) и запрет общих геометрических решателей.
   - Утверждён алгоритм площади для $n \ge 3$ (`ND-03`) и безразмерный критерий вырожденности + порог $\eta_{\text{deg}}$ (`ND-04`).
   - Утверждена политика переполнения/андерфлоу `L2` (`ND-05`: масштабирование `2^k` + overflow-safe проекция + `throw INVALID_COORDINATE` только при реальном выходе за `MAX_VALUE`).
   - Утверждены развязка `D-4`, модель допусков (`ND-06`) и контрактное решение по `D-5` (`ND-07`).
   - Подтверждена последовательность относительно `ROD-03` (`ND-11`).
2. **Фиксация совместимости `Contract 02` & `TRACE`:**
   - При изменении каких-либо полей `VerificationPredicates` или `VerifierTolerances` в `src/core/types.ts` явно зафиксирована обратная совместимость с `Contract 02 v2` (или решение о переходе на `v2.1` / `v3`).
3. **Запрет на преждевременный «золотой молоток»:**
   - Явно зафиксировано, что `ExactRational` в Phase 2.4 строится **в тестовом оракуле (`tests/`)**, а не как замена `Point2D` (`number`) в runtime `GeometryState` (что относится к Phase 2.5+ согласно `ND-08`).
   - Явно зафиксировано, что `Interval64` не внедряется в `L2`/`L7` на основе наивного `(1 ± EPSILON)` (согласно разделу 4.1 [OMR_PHASE_2_4_CRITICAL_AUDIT.md](./OMR_PHASE_2_4_CRITICAL_AUDIT.md)).
4. **Контрольная точка SHA-256 baseline:**
   - Перед началом правок повторно сверены SHA-256 и подтверждено прохождение всех `36/36` базовых тестов.
5. **Автономный прототип оракула в `tests/` (Gate 1):**
   - Первым шагом кодирования Phase 2.4 (до правок в `L2`/`L7`) создаётся независимый оракул (Уровни B/C) и фиксируются красные воспроизводящие тесты для `D-1..D-5` (включая негативный контроль `shift = 1e10 -> -8192`).
6. **Явная авторизация владельца на старт реализации Phase 2.4.**

## 3. Поэтапный план гейтов реализации (после снятия блокировки)

- **Gate 0 — Sign-off:** Владелец утверждает `ND-01..ND-11` и даёт явный старт Phase 2.4.
- **Gate 1 — Independent Oracle First (`tests/`):** Реализация `exactNumericalOracle` (Level B/C) без импортов из `src/core/`, воспроизведение всех текущих провалов `D-1..D-5` как красных тестов-характеристик.
- **Gate 2 — Surgical Hardening (`src/core/`):**
  - Фикс `D-4` (`areaEpsilon ?? DEFAULT_VERIFIER_TOLERANCES.areaEpsilon`).
  - Фикс `D-3` (масштабирование `2^k` + overflow-safe проекция в `L2` и Stage C в `L7`).
  - Фикс `D-1` (центрированная + точная диадическая/компенсированная площадь для любых $n$-угольников в `L7` + `orient2d` фильтр).
  - Фикс `D-2` и `D-5` строго по утверждённым вариантам `ND-04` и `ND-07`.
- **Gate 3 — Acceptance & Regression:**
  - `36/36` базовых тестов (с учётом явно авторизованных уточнений, если `ND-04`/`ND-07` меняют граничные кейсы) + 100% тестов оракула `O-1..O-7`.
  - Отсутствие `L2`/`L7` runtime-связности (`Contract 02` тест #12 + проверка запрета Common-Mode).
  - Чистые `tsc` (`lint` / typecheck) и `npm run build` (и при наличии возможности — параллельная фиксация наблюдения `D-8` в среде AI Studio).
