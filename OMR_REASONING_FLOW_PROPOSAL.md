# OMR — Reasoning Flow Proposal (`OMR_REASONING_FLOW_PROPOSAL.md`)

**Версия:** Cross-Architecture Audit v1.0 (проектное предложение по потоку рассуждения для `AI Skill`; программный код и `L1–L7` **не изменяются** `[E]`).  
**Цель (§4):** Определить операционный цикл совместной работы `CRP-01 / MCAR`, `PWRP v1.1` и `OMR L1–L7`, доказав необходимость возвратов управления и описав защиту от бесконечного перебора.

---

## 1. Почему 8-этапный поток НЕ может быть строго линейным

Исходная 8-шаговая цепочка:
```text
WHOLE OBJECT
 → CONSTRUCTION HYPOTHESES
 → COMPONENT DECOMPOSITION
 → JOINT / INTERFACE IDENTIFICATION
 → MATHEMATICAL MODEL
 → PHYSICAL CONSTRAINT ANALYSIS
 → OPERATION / ASSEMBLY PLAN
 → VERIFICATION
```
является правильной **базовой последовательностью по умолчанию** (каноническим прямым проходом), но **не может быть строго линейной (однонаправленной)** по трём объективным причинам `[D]`:

1. **Обратная связь от физики к происхождению (`PHYSICAL → HYPOTHESES`):**
   Если гипотеза `Single-Piece` успешно прошла геометрию (`WHOLE → MATH`), но `PHYSICAL CONSTRAINT ANALYSIS` (`PWRP-01 / 06 / 12`) выявляет неизбежный излом толстого листа, потерю устойчивости или недостижимость изгиба, агент должен уметь **вернуться** на этап `CONSTRUCTION HYPOTHESES` и переключиться на `Modular` или `Hybrid` (напр., разбить крыло на панели + жёсткую рейку).
2. **Обратная связь от плана сборки к интерфейсам (`ASSEMBLY PLAN → JOINTS`):**
   На этапе `OPERATION / ASSEMBLY PLAN` может выясниться, что внутренний клеевой/замковый шов физически невозможен при замыкании двух половин оболочки (`M4`: `PWRP-08 + 09`), хотя локально геометрия половин корректна. Управление возвращается к `JOINT / INTERFACE IDENTIFICATION` (пересмотр способа соединения на внешний замок/ленту или технологическое окно) либо к отказу (`CONSTRUCTIVELY_INFEASIBLE`).
3. **Двунаправленная конструктивная декомпозиция (`Construction Decomposition`):**
   В процессе сборки агент движется не только сверху вниз (`WHOLE → COMPONENTS → JOINTS`), но и снизу вверх (`COMPONENTS → JOINTS → ASSEMBLY → WHOLE`), проверяя, действительно ли собранные компоненты с учётом `offset` (`PWRP-05`), зазоров (`PWRP-03`) и допусков (`PWRP-07`) восстанавливают целевую `GLOBAL_GEOMETRY`.

## 2. Рекомендуемый поток с контролируемыми возвратами управления

```text
[1. WHOLE OBJECT / OBSERVATION]
        │  (Наблюдаемая глобальная геометрия, контекст, известные факты)
        ▼
[2. CONSTRUCTION HYPOTHESES (`MCAR`)] ◄──────────────────────────────────────┐
        │  Удерживает HYPOTHESIS_SET:                                        │
        │  {Single-Piece, Modular, Hybrid, Multi-Part Enclosure}             │
        ▼                                                                    │
[3. COMPONENT DECOMPOSITION (`MCAR`)]                                        │
        │  WHOLE ──► COMPONENTS (с ID и PROVENANCE или UNKNOWN)              │
        ▼                                                                    │
[4. JOINT / INTERFACE IDENTIFICATION (`MCAR`)] ◄───────────────────────┐     │
        │  JOINTS (ID, INTERFACES, JOINING_METHOD, REVERSIBILITY, DOF) │     │
        ▼                                                              │     │
[5. MATHEMATICAL MODEL (`OMR L1–L2` / формальное описание)]            │     │
        │  Отдельные GeometryState/TRACE (где применимо) + проверка L7 │     │
        │  (Если L7 FAIL по неверной трассе ──► пересчёт в [5] или [2])│     │
        ▼                                                              │     │
[6. PHYSICAL CONSTRAINT ANALYSIS (`PWRP v1.1`)]                        │     │
        │  Маршрутизация по JOINING_METHOD и свойствам компонентов     │     │
        ├──► (Отказ физики: не лезет 1 лист / разрушение) ────────────┼─────┘
        ▼                                                              │
[7. OPERATION / ASSEMBLY PLAN (`MCAR` + `PWRP-08/09`)]                 │
        │  ASSEMBLY_SEQUENCE + композиция ASSEMBLY ──► WHOLE           │
        └──► (Потеря доступа / buckling при сборке последнего шва) ────┘
        ▼
[8. MULTI-AXIS VERIFICATION (`L7` + `MCAR` + `PWRP-10`)]
        │  Итоговый трёхосевой вектор: (M_OMR, C_MCAR, P_PWRP-10)
        ▼
[Ответ пользователю / Запрос недостающих данных при UNKNOWN]
```

*Принцип разграничения точек верификации:* математическая проверка `L7` запускается **внутри этапа [5]** для каждого формализованного перехода, а не откладывается целиком на конец; этап **[8]** собирает финальный **трёхосевой вердикт** без подмены вердикта `L7`.

## 3. Поведение потока в пяти критических ситуациях (§4)

### Ситуация 1: Происхождение объекта `UNKNOWN`
- **Что происходит в [2]–[4]:** Агент не выбирает `Single-Piece` по умолчанию. В `HYPOTHESIS_SET` сохраняются все непротиворечащие наблюдаемой геометрии варианты (напр., `Single-Piece` vs `Modular` vs `Hybrid`), а `COMPONENT_PROVENANCE` фиксируется как `UNKNOWN`.
- **Что происходит в [5]–[8]:**
  - Агент **не запускает** слепой перебор 1-листовой развёртки в `L2`.
  - Физический анализ [6] переходит в режим **условной проверки по веткам (`CONDITIONAL_PER_HYPOTHESIS`)**: какие `PWRP` активируются при гипотезе `A`, а какие при `B`.
  - Финальный вердикт [8]: $\mathbf{C} = \text{AMBIGUOUS\_HYPOTHESES / PROVENANCE\_UNKNOWN}$, $\mathbf{P} = \text{INSUFFICIENT\_PHYSICAL\_CONTEXT}$ с конкретным запросом данных о числе заготовок и швах.

### Ситуация 2: Геометрия известна, но способ соединения `UNKNOWN`
- **Что происходит в [2]–[4]:** `COMPONENTS` и `INTERFACES` (швы/кромки/половины) могут быть уже выявлены по `GLOBAL_GEOMETRY`, но `JOINING_METHOD`, `JOINT_REVERSIBILITY` и `INTERFACE_DOF` остаются `UNKNOWN`.
- **Что происходит в [6]–[8]:**
  - Поскольку физика замка (`PWRP-04/12`) и физика клея (`PWRP-14/13`) **принципиально различны**, маршрутизатор `MCAR → PWRP` **запрещает подставлять тип шва по умолчанию**.
  - Вместо этого формируются альтернативные профили требований (если `POCKET_FLAP` — нужен клапан с глубиной и зазором; если `ADHESIVE` — площадь нахлёста, тип клея и доступ для прижима).
  - Финальный вердикт [8]: $\mathbf{P} = \text{INSUFFICIENT\_PHYSICAL\_CONTEXT}$ (не `PHYSICALLY_FEASIBLE` и не `PHYSICALLY_INFEASIBLE`).

### Ситуация 3: Конструкция математически корректна (`L7 PASS`), но физически не проверена
- **Что происходит в [5]–[8]:** Внутренние расчёты сгибов прошли `L7` (`PASS`), но отсутствуют данные о материале, толщине, инструменте или не проверялась устойчивость/трение.
- **Что происходит в [8]:** Трёхосевой вектор строго удерживает разделение:
  - $\mathbf{M}_{\text{OMR}} = \text{PASS}$;
  - $\mathbf{C}_{\text{MCAR}} = \text{VERIFIED\_...}$ (или `AMBIGUOUS_HYPOTHESES`);
  - $\mathbf{P}_{\text{PWRP-10}} = \text{PHYSICALLY\_NOT\_VERIFIED}$ (или `INSUFFICIENT_PHYSICAL_CONTEXT`) с точным перечнем непроверенных `PWRP`.
  - Запрещено сжимать это в формулировку «модель полностью валидна».

### Ситуация 4: Физическое ограничение требует изменения конструктивной гипотезы
- **Пример:** Попытка сделать длинный жёсткий пролёт или замкнутую коробку из одного тонкого листа проваливается в [6] по `PWRP-06/12` (недостаточная жёсткость / *buckling*) или `PWRP-01` (разрыв по $R_{\min}$).
- **Механизм возврата:** Физический отказ помечает текущую ветку гипотезы в `HYPOTHESIS_SET` как **`REFUTED_BY_PHYSICS`** (с указанием конкретного `PWRP` и причины) и передаёт управление вверх в **[2]** (`CONSTRUCTION HYPOTHESES`):
  - если задача допускает изменение конструкции (проектный режим), агент переходит к следующей гипотезе — например, `Modular` (усиленные двойные модули) или `Hybrid` (добавление ребра жёсткости / панели другого материала) и повторяет проход [3]–[8];
  - если конструктивное происхождение жёстко зафиксировано пользователем («строго 1 лист такого материала»), возврат запрещён и выносится честный отказ $\mathbf{P} = \text{PHYSICALLY\_INFEASIBLE}$.

### Ситуация 5: Предотвращение бесконечного перебора вариантов (Anti-Loop & Anti-Explosion Protocol)
Агент защищается от комбинаторного взрыва и зацикливания **пятью жёсткими механизмами**:
1. **Монотонное вычеркивание (`No-Reopen Rule`):** гипотеза, получившая `REFUTED` (топологически или физически при фиксированных условиях), не переоткрывается повторно, если не поступили новые входные данные от пользователя.
2. **Ограниченный бюджет гипотез:** в `HYPOTHESIS_SET` порождаются только макро-классы (`Single-Piece`, `Modular`, `Hybrid`, `Multi-Part Enclosure`), а не все перестановки $N!$ разбиений граней. При неизвестных деталях агент **не перебирает** произвольные внутренние клапаны, а немедленно сворачивает их в `UNKNOWN`.
3. **Немедленный стоп-сигнал от `UNKNOWN`:** если критический параметр (`COMPONENT_PROVENANCE`, `JOINING_METHOD`, марка материала) отсутствует, дальнейший детальный физический/сборочный перебор прерывается выходом в `INSUFFICIENT_PHYSICAL_CONTEXT` (допустимо не более 1 условного обзора альтернатив).
4. **Ограничение глубины возвратов (`Max Backtrack Depth`):** разрешён максимум 1 переход по смене конструктивного режима в одном цикле анализа без подтверждения пользователя (чтобы агент не перебирал самопроизвольно десятки экзотических гибридов).
5. **Разделение ролей:** в `L2` передаются только уже сформированные конкретные `OperationRequest` (`Single-Piece` или конкретный модуль), поэтому математическое ядро никогда не используется как слепой переборщик гипотез.
