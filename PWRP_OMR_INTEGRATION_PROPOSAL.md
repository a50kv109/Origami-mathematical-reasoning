# PWRP — OMR Architectural Integration Proposal (`PWRP_OMR_INTEGRATION_PROPOSAL.md`)

**Версия:** Research Task v1.0  
**Опорная архитектура:** `docs/ARCHITECTURE.md` (`v0.1.0`, семислойная архитектура `L1–L7`, `AI Skill`, `Tool Integration Layer` `[E]`).  
**Жёсткие ограничения (§7):** Не изменять `L2 Geometry Core`, `L7 Independent Verification`, `Contract 02` и `Property F Test Layer`; не вводить новые вычислительные примитивы без отдельного обоснования; не объявлять PWRP готовым программным модулем `[E]`.

## 1. Ключевой архитектурный вопрос (§7)

> *Нужно ли PWRP отдельное место в вычислительном ядре (новый слой `L8` или встраивание в `L2`/`L7`), или достаточно библиотеки паттернов рассуждения, подключаемой к AI-агенту по необходимости?*

### Ответ и сравнительный анализ вариантов

| Критерий | Вариант A: Встроить PWRP внутрь `L2` / `L7` / `Property F` | Вариант B: Новый вычислительный слой в ядре (напр., `L_phys`) | Вариант C (Рекомендуемый `[D][H]`): Библиотека паттернов в контуре `AI Skill` (Planner / Reasoner) + опциональный будущий физический модуль в `Phase 5+` |
| :--- | :--- | :--- | :--- |
| **Сохранность `L2`, `L7`, `Contract 02`, `Property F`** | **Нарушается** (смешение чистой математики и эмпирических параметров материала) | Не трогает `L2`, но меняет каноническую 7-слойную схему до реализации `L3–L6` | **100% сохранность:** ни один существующий контракт и ни один тест не затрагивается `[E]`. |
| **Соблюдение разделения проекций состояния (`ARCHITECTURE.md §1`)** | **Нарушается** (`S` становится монолитом геометрии и физики) | Формально сохраняется только при полном определении контрактов `L2↔L3↔L_phys` | **Соблюдается:** ядро хранит проекцию геометрии/топологии, а `AI Skill` агрегирует физический контекст при планировании. |
| **Зависимость от `L3` (Layer Order) и `L4` (Kinematics)** | Прямой блокер (сейчас в `L2` 2D нет кратности слоёв и траекторий `γ(t)`) | Преждевременно: без `L3` (Phase 5) физическая толщина/слои лишены входной топологии | **Гибкость:** уже сейчас в `AI Skill` паттерны `PWRP-01..10` работают как дисциплина вопросов и эпистемической честности (`NOT VERIFIED` / `Insufficient Context`). |
| **Риск выдумывания произвольных чисел** | Высокий (код требует жёстких `if (thickness > ...)`) | Высокий до калибровки на физических образцах | **Минимальный:** описательные паттерны не придумывают пороги без данных. |

**Рекомендация:** На текущем этапе OMR (`Phase 2.3.x` / подготовка `Phase 3–8`) **PWRP должен развиваться исключительно как библиотека паттернов рассуждения (`Knowledge & Reasoning Pattern Library`) в слое `AI Skill`**, а не как вычислительный модуль ядра `[D][H]`. Если в будущих фазах (`Phase 5+`, после появления 3D `L2`, `L3 Layer Order` и `L4 Kinematics`) потребуется автоматический физический расчёт (например, оценка offset или коллизии объёмов), он подключается как **отдельный внешний проверяющий/физический модуль** со своим контрактом, не меняющим `L2` и `L7`.

## 2. Поток взаимодействия `AI Skill (PWRP)` с `L1–L7` без нарушения контрактов

```text
[Пользовательский запрос / Физический контекст]
        │  (материал, толщина, среда, инструмент — или их отсутствие)
        ▼
[AI Skill + Библиотека PWRP-01..10]  ◄──(только чтение паттернов, ZERO правок в Core!)
   ├──► 1. Формирует Trust Boundary: Trusted OperationRequest ──► [L2 Geometry Core] ──► [TRACE]
   │                                                                                         │
   │                                                                                         ▼
   ├──► 2. Получает математический вердикт:  PASS / FAIL / UNDETERMINED ◄──────── [L7 Verifier]
   │                                          (+ в тестах: Property F Test Layer v1)
   │
   └──► 3. Применяет PWRP-10 (Epistemic Adjudication):
           • Отделяет Математический вердикт (L7) от Физической оценки (PWRP);
           • При отсутствии L3 / параметров материала выставляет:
             Geometry: VALID (L7 PASS) | Physical Feasibility: NOT VERIFIED / INSUFFICIENT CONTEXT;
           • Никогда не подменяет вердикт L7 и не выдаёт L7 PASS за физическую выполнимость!
```

### Контрактные границы между слоями (что берёт и НЕ берёт на себя `PWRP`)

1. **`L2 Geometry Core` (`src/core/l2GeometryEngine.ts`):**
   - Сохраняет чистую евклидову математику (`ℝ²`, позже `ℝ³`).
   - Не знает о бумаге, миллиметрах толщины, `tau_material`, радиусе изгиба или трении.
2. **`L3 Layer Order` (запланирован на Phase 5 `[E]`):**
   - В будущем именно `L3` сможет поставлять комбинаторную информацию о порядке наложения граней — то есть локальную кратность $n(x)$ для `PWRP-07` (`Layer Accumulation`), **не** вычисляя саму механику.
3. **`L4 Kinematic Layer` (запланирован на Phase 5 `[E]`):**
   - Непрерывные траектории $\gamma(t)$ станут естественной основой для анализа достижимости и предотвращения коллизий по пути (`PWRP-03`, `PWRP-08`, `PWRP-09`).
4. **`L7 Independent Verification` (`src/core/l7IndependentVerifier.ts`) и `Property F Test Layer`:**
   - Проверяют исключительно математические аксиомы и контракт `OperationRequest ↔ Witness ↔ Result` в $\tau_{\text{geometry}}$.
   - Даже в будущем `L7` не должен «ослаблять» $\tau_{\text{geometry}}$ из-за толщины материала (правило $\tau_{\text{geometry}} \neq \tau_{\text{material}} \neq \tau_{\text{fabrication}}$).
5. **`AI Skill` + `PWRP` (Phase 8 / слой рассуждений `[E][H]`):**
   - Не имеет права выставлять `L7 PASS` (`docs/ARCHITECTURE.md §4` `[E]`).
   - Использует библиотеку `PWRP-01..10` как **чеклист рассуждения и распознавания рисков**:
     - выявляет, какие физические факторы активированы планом операций;
     - диагностирует нехватку входных данных (`PWRP-01`, `02`, `09`);
     - удерживает 5 раздельных эпистемических статусов (`PWRP-10`).

## 3. Проекция пяти физических характеристик контекста на схему данных OMR (концептуально, без кода)

Ранее предложенные характеристики физического контекста (`MATERIAL`, `THICKNESS`, `LAYER_MULTIPLICITY`, `BEND_CAPABILITY`, `SPATIAL_CLEARANCE`) сопоставляются с паттернами `PWRP` и источниками данных в OMR:

| Характеристика контекста | Связанные паттерны PWRP | Источник в целевой системе (без изменения `GeometryState` в 2.3.x) | При отсутствии источника |
| :--- | :--- | :--- | :--- |
| `MATERIAL` | `PWRP-01`, `PWRP-02`, `PWRP-04`, `PWRP-06` | Внешний мета-контекст запроса пользователя / спецификация материала (вне `GeometryState`) | Статус `Insufficient Physical Context` |
| `THICKNESS` | `PWRP-01`, `PWRP-03`, `PWRP-05`, `PWRP-07` | Паспорт материала (отдельная физическая проекция в будущих фазах) | Не подставлять «дефолт»; статус `Insufficient Context` |
| `LAYER_MULTIPLICITY` | `PWRP-07`, `PWRP-03`, `PWRP-06` | Будущий `L3 Layer Order` (число перекрывающих граней $n(x)$) | Статус `Physically Not Verified` (указать, что кратность не вычислена) |
| `BEND_CAPABILITY` | `PWRP-01`, `PWRP-05`, `PWRP-06`, `PWRP-09` | Паспорт материала + параметры инструмента/оснастки (`R_min`, усилие) | Статус `Physically Not Verified` / запрос данных об инструменте |
| `SPATIAL_CLEARANCE` | `PWRP-03`, `PWRP-04`, `PWRP-08` | Будущие `3D L2` + `L3` + `L4` (оценка зазоров и траекторий) | Статус `Physically Not Verified` |

Это строго соблюдает фундаментальный принцип из `docs/ARCHITECTURE.md §1`: *«запрещено объединять все характеристики объекта в единый монолитный кортеж»* `[E]`.

## 4. Эволюционный план интеграции (Roadmap без нарушения текущих фаз)

1. **Этап 0 (Текущий — завершено этим исследованием):** Зафиксировать онтологию `PWRP-01..10`, эпистемическую дисциплину (`PWRP-10`) и строгое разведение допусков (`PWRP_RESEARCH_REPORT.md`). Нулевое влияние на `Phase 2.3.3` и `Phase 2.4`.
2. **Этап 1 (Интеграция в контур `AI Skill` — без вычислительных примитивов):**
   Подключение текстовых/структурированных паспортов `PWRP-01..10` как справочника рассуждений агента при разборе задач пользователя (агент учится отвечать «геометрически `VALID`, физически `NOT VERIFIED` по причинам X, Y», а не выдавать математику за физическую гарантию).
3. **Этап 2 (После реализации `3D L2` и `L3 Layer Order` в Phase 5+):**
   Поставка из `L3` точной локальной кратности $n(x)$ и графа закрытия доступа (`PWRP-07`, `PWRP-08`) без изменения самих формул геометрии `L2`.
4. **Этап 3 (Эмпирическая калибровка и опциональный Physical Feasibility Checker):**
   Только после экспериментов с реальными материалами — формализация и проверка отдельных числовых моделей (`offset`, предел $R_{\min}(T)$) как самостоятельного внешнего контура верификации (аналогично тому, как `Tool Integration` использует Zero-Trust Import).
